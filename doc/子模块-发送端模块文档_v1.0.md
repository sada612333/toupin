## 发送端模块文档

### 一、现有基础功能
- 基于 Jetpack Compose 搭建简单操作界面
- 屏幕内容采集
- 基础音视频编码
- 基于 WebRTC 实现局域网投屏传输

### 二、详细优化需求

#### 1. 界面布局优化（基于 Jetpack Compose）
- 适配手机/平板等不同安卓机型
- 利用 Jetpack Compose 的自适应布局特性
- 简化投屏操作步骤，优化按钮布局与视觉效果
- 统一界面风格，封装可复用 Compose 组件
- 解决不同机型显示错乱问题

#### 2. 连接相关优化（核心适配）
- 基于现有 WebRTC 局域网连接，适配多连接方式（热点、二维码）
- 确保与接收端连接同步
- 优化自身连接触发、状态反馈逻辑
- 解决连接触发繁琐、状态显示不清晰问题
- 详细细则见「连接细节文档」

#### 3. 性能相关优化（核心适配）
- 优化自身屏幕采集、音视频编码逻辑
- 适配性能监控数据采集要求
- 确保采集、编码环节的性能数据可精准上报
- 解决采集卡顿、编码耗时过长问题
- 详细细则见「性能优化与监控文档」

### 三、核心逻辑
```
基于 Jetpack Compose 加载操作界面
        ↓
采集屏幕画面
        ↓
音视频编码
        ↓
调用连接模块发送数据（参考连接细节文档）
        ↓
调用性能监控模块采集数据（参考性能优化与监控文档）
        ↓
接收连接与性能反馈，在 Compose 界面显示投屏状态
```

### 四、依赖资源
- 安卓原生采集 API
- 编码工具
- 网络权限
- 热点/二维码相关 API
- 性能采集工具
- Jetpack Compose 框架依赖
- WebRTC 核心 SDK 及相关依赖

### 五、编码要求
- 保证单一功能点可验证、可测试
- 每个功能点（如屏幕采集、编码传输、界面交互）均设计独立测试用例
- 日志输出遵循统一规范：
  - 日志级别：DEBUG/INFO/WARN/ERROR
  - 日志格式：时间戳 | 模块名称 | 功能点 | 日志内容 | 异常信息（如有）
  - 确保日志可追溯、便于问题定位
