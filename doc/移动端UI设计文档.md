# 移动端UI设计文档

## 一、Sender 发送端 UI 设计

### 1. 页面布局

```
┌─────────────────────────────┐
│ 顶部：App标题栏 + 投屏状态指示灯    │
├─────────────────────────────┤
│                             │
│ 中部：                       │
│  · 连接信息卡片（IP+端口）      │
│  · 已连接设备列表              │
│  · 错误提示区（仅异常时显示）     │
│                             │
├─────────────────────────────┤
│ 底部：主操作按钮（开始/停止投屏）  │
└─────────────────────────────┘
```

### 2. UI 组件清单

| 组件 | 说明 |
|------|------|
| **状态指示灯** | 圆形色点，Idle=灰色，Connecting=橙色脉冲动画，Ready=绿色，Error=红色 |
| **状态文本** | 紧跟指示灯，显示当前状态描述文字 |
| **连接信息卡片** | Ready状态下展示，含 `ws://{ip}:{port}` 地址，带一键复制按钮 |
| **WiFi状态警告条** | 非WiFi网络时顶部显示黄色警告条 |
| **已连接设备列表** | 每项显示设备名/会话ID + 断开按钮（可选）。**列表为空时**：显示空状态占位，含设备图标 + 提示文字"等待设备连接..."，引导用户将地址分享给Receiver；**列表非空时**：显示设备条目列表，每条显示设备序号/名称 + 连接时长（可选） |
| **错误卡片** | Error状态显示，含警告图标 + 错误描述 + 重试按钮 |
| **主操作按钮** | 大号FAB或全宽按钮，Idle→"开始投屏"，Ready→"停止投屏"（红色） |
| **权限引导弹窗** | 首次点击开始投屏时，解释需要屏幕录制权限 |

### 3. 用户操作流程

```
启动App → [Idle状态]
  │
  ├─ 非WiFi？→ 顶部显示警告条（仍可操作）
  │
  ↓ 点击"开始投屏"
  │
  ├─ 弹出权限引导弹窗（解释为何需要屏幕录制权限）
  ↓ 确认授权
  │
  ├─ 系统MediaProjection授权弹窗
  ↓ 用户授权
  │
  → [Connecting状态] 橙色脉冲动画
  │
  ├─ 成功 → [Ready状态] 绿色指示灯
  │         显示连接信息卡片：ws://192.168.1.100:8888
  │         等待Receiver连接...
  │         Receiver接入 → 设备列表新增一条
  │         Receiver断开 → 设备列表移除（静默，不弹提示）
  │
  ├─ 失败 → [Error状态] 红色指示灯
  │         显示错误卡片（权限拒绝/端口占用/采集异常）
  │         点击"重试" → 回到Idle → 重新走流程
  │
  ↓ 点击"停止投屏"
  │
  → [Idle状态] 断开所有Receiver，释放资源
```

### 4. 视觉层级

| 优先级 | 元素 | 视觉处理 |
|--------|------|----------|
| **P0 最突出** | 主操作按钮（开始/停止投屏） | 全宽大按钮，主色调，底部固定 |
| **P1 突出** | 投屏状态指示灯+文本 | 顶部固定，颜色+动画强区分 |
| **P2 重要** | 连接信息卡片（IP:Port） | 卡片式容器，等宽字体，复制按钮醒目 |
| **P3 辅助** | 已连接设备列表 | 简洁列表，次要文字色 |
| **P4 警示** | WiFi警告条 / 错误卡片 | 黄色/红色背景，图标+文字 |

## 二、Receiver 接收端 UI 设计

### 1. 页面布局

**未连接状态（Idle / Listening / Connecting）：**

```
┌─────────────────────────────┐
│ 顶部：App标题栏              │
├─────────────────────────────┤
│                             │
│ 中部：                       │
│  · 连接地址输入区             │
│  · 连接状态提示              │
│  · 错误提示区（仅异常时显示）  │
│  · 历史连接记录（可选）        │
│                             │
├─────────────────────────────┤
│ 底部：连接/取消按钮           │
└─────────────────────────────┘
```

**已连接状态（Connected）：**

```
┌─────────────────────────────┐
│ 全屏视频画面                  │
│                             │
│  ┌───────────────────────┐  │
│  │ 顶部浮层（半透明）：      │  │
│  │  · 连接状态指示灯        │  │
│  │  · Sender地址           │  │
│  │  · 断开按钮             │  │
│  └───────────────────────┘  │
│                             │
└─────────────────────────────┘
```

### 2. UI 组件清单

| 组件 | 说明 |
|------|------|
| **地址输入框** | 输入 `ws://{ip}:{port}`，支持IP:Port格式自动补全 `ws://` 前缀 |
| **连接按钮** | Idle时可用，"连接" |
| **取消按钮** | Listening/Connecting时替代连接按钮，"取消" |
| **状态提示文本** | Idle→"输入Sender地址"，Listening→"正在连接..."，Connecting→"正在协商..." |
| **错误提示区** | 连接失败/协商失败时显示，含警告图标 + 错误描述（如"无法连接到该地址"、"协商失败"），仅异常时出现 |
| **重连指示条** | 断连重连时顶部显示"重连中...（第N次）"，带取消按钮 |
| **SurfaceViewRenderer** | 全屏视频渲染，SCALE_ASPECT_FIT自适应 |
| **顶部浮层** | Connected状态半透明覆盖，显示连接信息+断开按钮，3秒无操作自动隐藏 |
| **停止通知弹窗** | 收到Sender的stop消息，弹窗提示"发送端已停止投屏"，确认后回退Idle |
| **历史连接记录** | 可选，展示最近连接过的地址列表，点击快速填入 |

### 3. 用户操作流程

```
启动App → [Idle状态]
  │
  ↓ 输入Sender地址（如 192.168.1.100:8888）
  ↓ 点击"连接"
  │
  → [Listening状态] "正在连接..."
  │
  ├─ WebSocket连接成功 → [Connecting状态] "正在协商..."
  │   │
  │   ├─ SDP协商完成 → [Connected状态]
  │   │   全屏显示视频画面
  │   │   点击画面 → 显示/隐藏控制浮层
  │   │   点击断开 → [Idle状态]
  │   │
  │   └─ 协商失败 → [Listening状态] 自动重连
  │
  ├─ WebSocket连接失败 → [Listening状态] 自动重连
  │   3秒间隔，无限重试
  │   顶部显示"重连中...（第N次）"
  │   点击"取消" → [Idle状态]
  │
  ├─ 运行中断连 → [Listening状态] 自动重连
  │
  ├─ 收到stop消息 → 弹窗"发送端已停止投屏"
  │   确认 → [Idle状态]（终止重连，释放资源）
  │
  ↓ 点击"取消"（Listening/Connecting时）
  │
  → [Idle状态] 终止重连
```

### 4. 视觉层级

| 优先级 | 元素 | 视觉处理 |
|--------|------|----------|
| **P0 最突出** | 视频画面 | 全屏渲染，其他元素浮层覆盖 |
| **P1 突出** | 地址输入框 + 连接按钮 | 未连接时的核心交互，居中大面积展示 |
| **P2 重要** | 连接状态提示 / 重连指示条 / 错误提示区 | 文字+颜色区分，顶部/中部固定 |
| **P3 辅助** | 顶部控制浮层（断开按钮） | 半透明背景，自动隐藏，点击唤出 |
| **P4 警示** | 停止通知弹窗 | 模态弹窗，必须用户确认 |

## 三、两端状态色彩体系统一

| 状态 | 色值建议 | 用途 |
|------|----------|------|
| Idle | `Grey 500` (#9E9E9E) | 指示灯、状态文字 |
| Connecting/Listening | `Orange 500` (#FF9800) | 脉冲动画 |
| Ready/Connected | `Green 500` (#4CAF50) | 稳定状态 |
| Error | `Red 500` (#F44336) | 错误指示灯、错误卡片 |
| Warning | `Amber 400` (#FFC107) | WiFi警告条 |

## 四、设备自适应要点

根据技术方案文档中 `DeviceLayoutType` 的定义：

| 设备类型 | 布局差异 |
|----------|----------|
| **手机竖屏** | Sender：标准竖屏布局；Receiver：视频画面+顶部浮层 |
| **手机横屏** | Sender：布局不变；Receiver：视频全屏，顶部浮层 |
| **平板横屏** | Receiver：视频全屏沉浸，顶部浮层间距更宽松 |
| **TV横屏** | Receiver：纯全屏无浮层（遥控器操作），D-Pad焦点导航 |
