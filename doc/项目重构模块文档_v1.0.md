## 项目重构模块文档

### 一、重构目标
- 优化项目结构，拆分冗余代码
- 明确各模块职责，降低维护成本
- 便于后续扩展
- 优化 Jetpack Compose 组件复用性
- 完善 WebRTC 传输架构

### 二、现有架构痛点
- 发送端与接收端存在大量重复代码（如工具类、权限管理、性能采集基础逻辑、Jetpack Compose 通用组件、WebRTC 公共配置）
- 层级划分不清晰，部分代码耦合度高
- WebRTC 传输逻辑与业务逻辑耦合
- Jetpack Compose 组件设计不合理

### 三、重构方向

#### 1. 提取公共模块
- 整合重复代码
- 包含 Jetpack Compose 通用组件
- 包含 WebRTC 公共配置及工具类

#### 2. 明确层级职责
- 基础层：提供底层基础能力
- 核心层：业务逻辑处理
- 应用层：UI 展示与交互
- 避免跨层调用

#### 3. 优化模块划分
- 分离业务逻辑与 UI 逻辑（Jetpack Compose 相关）
- 分离 WebRTC 传输逻辑与业务逻辑
- 将连接、性能相关的公共逻辑融入公共模块

#### 4. 同步优化补充文档
- 优化「连接细节文档」逻辑
- 优化「性能优化与监控文档」逻辑


- 确保核心模块与补充文档衔接顺畅

### 四、重构约束
- 不影响现有基础投屏功能及 WebRTC 局域网传输能力
- 确保重构后功能正常运行，兼容原有安卓版本及 Jetpack Compose、WebRTC 版本
- 重构后编码需遵循「单一功能点可验证、可测试」原则
- 统一日志结构规范

### 五、编码补充要求
- 重构后的代码需拆分单一功能模块，每个功能点可独立测试、单独验证，避免功能耦合
- 日志结构统一规范，明确日志输出规则，确保重构后日志可追溯、便于问题定位


- 补充文档需与核心模块同步重构，确保内容一致、无重复

### 六、依赖适配要求
- 重构时可对依赖组件进行升级
- 需重点注意各组件与 kitlon、gradle、安卓 gradle 插件之间的适配性
- 提前排查版本冲突，确保升级后项目可正常编译运行
