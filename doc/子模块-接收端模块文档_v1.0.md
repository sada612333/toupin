## 接收端模块文档

### 一、现有基础功能
- 基于 Jetpack Compose 搭建简单状态显示界面
- 基于 WebRTC 实现局域网连接接收
- 音视频解码
- 投屏内容显示
- 简单状态提示

### 二、详细优化需求

#### 1. 界面布局优化（基于 Jetpack Compose）
- 适配安卓电视/盒子的屏幕比例
- 利用 Jetpack Compose 的大屏适配特性
- 优化状态显示界面（显示连接状态、性能数据、投屏来源等）
- 增加操作便捷性（如一键断开连接、切换显示模式）
- 提升界面美观度，封装大屏专用 Compose 组件
- 确保操作流畅性

#### 2. 连接相关优化（核心适配）
- 适配多连接方式（局域网 WebRTC、热点、二维码）
- 优化自身连接响应、保活逻辑
- 处理连接异常场景，确保与发送端连接兼容
- 解决连接响应慢、易断连问题
- 详细细则见「连接细节文档」

#### 3. 性能相关优化（核心适配）
- 优化自身音视频解码、画面渲染逻辑
- 适配性能监控数据采集要求
- 确保解码、显示环节的性能数据可精准上报
- 解决解码延迟、音画不同步问题
- 详细细则见「性能优化与监控文档」

### 三、核心逻辑
```
基于 Jetpack Compose 加载显示界面
        ↓
调用连接模块监听连接请求（参考连接细节文档）
        ↓
接收发送端数据
        ↓
音视频解码
        ↓
优化画面渲染输出
        ↓
调用性能监控模块采集数据（参考性能优化与监控文档）
        ↓
反馈连接与性能状态至 Compose 界面
```

### 四、依赖资源
- 安卓原生解码 API
- 显示组件
- 网络权限
- 热点/二维码相关 API
- 性能采集工具
- Jetpack Compose 框架依赖
- WebRTC 核心 SDK 及相关依赖

### 五、编码要求
- 保证单一功能点可验证、可测试
- 每个功能点（如数据接收、解码显示、连接异常处理）均设计独立测试用例
- 日志输出遵循统一规范：
  - 明确日志级别、格式
  - 区分不同模块、不同功能点的日志
  - 包含关键操作记录、异常信息及上下文
  - 便于问题排查和功能验证
