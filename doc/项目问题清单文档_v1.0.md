## 项目问题清单

### 一、核心待解决问题

#### 问题1：界面布局不合理
- **问题描述**：发送端与接收端操作界面过于简单，用户操作路径不清晰
- **背景**：当前仅实现基础投屏功能，基于 Jetpack Compose 的 UI 未做适配优化
- **代码现状**：
  - 发送端 `MainActivity.kt`：仅包含"屏幕共享"标题、状态文本和开始/停止按钮，无美观性设计
  - 接收端 `MainActivity.kt`：仅包含简单输入框和按钮，未针对大屏设备优化
- **不符合文档要求**：文档要求"适配手机/平板等不同安卓机型"、"优化按钮布局与视觉效果"、"适配安卓电视/盒子的屏幕比例"

#### 问题2：连接方式单一
- **问题描述**：仅支持 WebRTC 局域网连接，无备用连接方案
- **背景**：现有连接方式易受网络环境影响，部分设备无法正常连接
- **代码现状**：
  - 发送端通过 WebSocket 信令服务器建立 WebRTC 连接
  - 接收端需手动输入发送端 IP 地址
- **不符合文档要求**：文档要求"扩展连接方式（新增热点连接、二维码连接）"、"优化设备搜索算法"

#### 问题3：无性能监控机制
- **问题描述**：投屏卡顿、断连无法定位原因，缺乏性能数据采集
- **背景**：基于 WebRTC 传输的投屏过程中存在画面延迟等问题，缺乏数据支撑
- **代码现状**：
  - 无性能数据采集逻辑
  - 无性能指标监控（延迟、帧率、CPU/内存占用等）
- **不符合文档要求**：文档要求"集成性能采集逻辑"、"监控数据采集频率"、"异常数据判定标准"

#### 问题4：项目架构冗余
- **问题描述**：发送端与接收端存在代码重复，模块职责不清晰
- **背景**：初期快速实现基础功能，未进行架构设计
- **代码现状**：
  - `ScreenShareService.kt` 和 `WebRTCPeerManager.kt` 均有 WebRTC 初始化逻辑
  - 两端 WebRTC 管理类设计不一致（`WebRTCPeerManager` vs `WebRTCManager`）
  - 缺乏公共模块提取
- **不符合文档要求**：文档要求"提取公共模块，整合重复代码"、"分离业务逻辑与 UI 逻辑"

### 二、次要待解决问题

#### 问题5：操作流程复杂
- **问题描述**：用户投屏操作步骤繁琐，学习成本高
- **代码现状**：发送端需手动点击按钮、授权屏幕共享权限，流程不够流畅

#### 问题6：状态反馈不清晰
- **问题描述**：连接状态、投屏状态等信息展示不够直观
- **代码现状**：仅显示简单文本状态，缺乏进度指示和错误提示

#### 问题7：缺乏连接重试机制
- **问题描述**：连接失败后需手动重新连接，用户体验差
- **代码现状**：接收端虽有部分重连逻辑，但发送端无重连机制

#### 问题8：无连接进度显示
- **问题描述**：用户无法了解连接建立的进度
- **代码现状**：无连接进度条或进度提示

### 三、潜在问题

#### 问题9：设备兼容性风险
- **问题描述**：不同品牌、型号的安卓设备可能存在兼容性问题
- **代码现状**：WebRTC 编解码配置未做充分兼容性处理

#### 问题10：网络环境适配不足
- **问题描述**：复杂网络环境下投屏稳定性难以保证
- **代码现状**：未针对不同网络环境做优化处理

#### 问题11：资源释放不完善
- **问题描述**：异常退出时可能存在资源泄漏
- **代码现状**：资源释放逻辑存在潜在问题（如 `VideoRendererLayout.release()` 中未正确检查空指针）

#### 问题12：缺乏日志规范
- **问题描述**：日志输出格式不统一，不利于问题定位
- **代码现状**：日志格式各异，无统一规范

### 四、代码质量问题

#### 问题13：代码重复
- `ScreenShareService.kt` 和 `WebRTCPeerManager.kt` 存在重复的 WebRTC 初始化代码
- 发送端和接收端的 WebRTC 管理逻辑相似但未复用

#### 问题14：错误处理不完善
- 部分异常场景未做处理（如 `VideoRendererLayout.setVideoTrack()` 中未处理空指针）
- 错误信息不够详细，难以定位问题根因

#### 问题15：硬编码值过多
- IP 地址默认值硬编码为 `"192.168.10.13"`
- 端口号硬编码为 `8080`
- 缺乏配置化管理

#### 问题16：缺乏单元测试
- 核心逻辑未编写单元测试
- 无法保证代码质量和可维护性
