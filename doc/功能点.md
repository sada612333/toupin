# 投屏 APP 迭代开发计划


我将按照最小可用改动的原则，为您拆解这个投屏 APP 的迭代开发计划。每个阶段都是一个完整可验证的功能点。

## 迭代开发计划（发送端优先）

---

## 阶段一：发送端 UI 骨架（Week 1）

**目标**：建立发送端项目，实现投屏状态的控制和展示

### 功能点 1.1
- 使用 Jetpack Compose 创建发送端项目
- 实现单一界面：显示当前连接状态（未连接/连接中/已连接）
- 实现单一按钮：点击触发状态切换（模拟，无实际功能）
- 编写 Compose UI 测试，验证状态显示和按钮点击

### 功能点 1.2
- 引入 ViewModel 管理投屏状态
- 实现状态机：Idle → Connecting → Connected → Error
- 状态变化时 UI 自动响应
- 编写 ViewModel 单元测试，验证状态流转

### 功能点 1.3
- 添加前台 Service 框架（空实现）
- 点击"开始投屏"按钮时启动 Service
- 显示前台通知，点击通知可回到应用
- 验证 Service 生命周期与 UI 状态同步

**阶段一验收**：应用可安装运行，状态切换流畅，Service 保活正常
---

## 阶段二：屏幕捕获（Week 2）

**目标**：实现屏幕捕获，本地预览验证

### 功能点 2.1
- 申请 MediaProjection 权限
- 实现权限申请流程（系统弹窗 + 引导说明）
- 权限结果回调处理（同意/拒绝/永久拒绝）
- 测试各种权限场景的 UI 表现

### 功能点 2.2
- 集成 MediaProjection 到 Service
- 创建 VirtualDisplay，捕获屏幕数据
- 本地 SurfaceView 预览（仅验证捕获成功）
- 验证预览画面与实际操作同步

### 功能点 2.3
- 添加捕获控制（开始/停止）
- 停止时正确释放 VirtualDisplay
- 处理配置变化（旋转）不中断捕获
- 内存监控，确保无泄漏

**阶段二验收**：点击开始投屏，能看到自己的手机屏幕被捕获并预览
---

## 阶段三：WebRTC 发送（Week 3-4）

**目标**：将捕获的画面通过 WebRTC 输出

### 功能点 3.1
- 集成 WebRTC 库（google-webrtc:1.0.32006）
- 初始化 PeerConnectionFactory
- 验证 WebRTC 初始化成功（日志输出）
- 处理 so 库加载失败等异常情况

### 功能点 3.2
- 创建 VideoSource 和 VideoTrack
- 将 MediaProjection 的 Surface 与 VideoSource 绑定
- 本地视频渲染验证（WebRTC 提供的预览）
- 确认视频流进入 WebRTC 管道

### 功能点 3.3
- 实现 PeerConnection（仅创建，无连接）
- 创建 DataChannel（预留，空实现）
- 生成 Offer SDP
- SDP 内容日志输出，人工检查格式

### 功能点 3.4
- 实现简易信令：将 SDP 显示在屏幕上（文本形式）
- 用户可手动复制 SDP
- 预留 Answer SDP 输入框（UI 占位）
- 验证 Offer/Answer 交换流程（人工复制粘贴）

### 功能点 3.5
- 实现 ICE 候选收集
- 收集完成后统一发送（Trickle ICE 简化版）
- 连接状态监控（日志输出）
- 连接成功时更新 UI 状态

**阶段三验收**：SDP 可在 PC 浏览器中设置，WebRTC 连接建立成功（无画面也显示连接状态）
---

## 阶段四：PC 浏览器接收（Week 5）

**目标**：PC 端用浏览器播放 WebRTC 流

### 功能点 4.1
- 创建 PC 测试网页（receiver.html）
- 实现 RTCPeerConnection 基础代码
- 提供 SDP 输入框和设置按钮
- 验证 JS 侧 PeerConnection 创建成功

### 功能点 4.2
- 实现 SDP 粘贴设置流程
- 生成 Answer SDP 并显示
- 用户将 Answer 粘贴回手机端
- 完成手动信令交换，连接建立

### 功能点 4.3
- 实现视频接收和播放
- 远端视频流渲染到 video 标签
- 连接状态显示（连接中/已连接/断开）
- 统计信息显示（分辨率、码率，可选）

### 功能点 4.4
- 优化信令流程（可选）
- 局域网内简易 HTTP 服务器广播 SDP
- 或二维码传输 SDP
- 减少手动复制粘贴步骤

**阶段四验收**：手机开始投屏，PC 浏览器能看到手机画面，延迟 < 500ms 可接受
---

## 阶段五：接收端项目（Week 6）

**目标**：建立接收端项目，基础框架

### 功能点 5.1
- 创建接收端项目（Jetpack Compose）
- 实现单一全屏界面：显示连接状态
- 实现单一按钮：开始监听/停止监听
- 编写基础 UI 测试

### 功能点 5.2
- 引入 ViewModel 管理接收状态
- 实现状态机：Idle → Listening → Connecting → Connected
- 状态变化驱动 UI 更新
- 单元测试验证状态流转

### 功能点 5.3
- 添加前台 Activity 保活（车机场景）
- 全屏显示，隐藏系统导航栏
- 处理车机常见分辨率（1920×720 等）
- 横屏锁定

### 功能点 5.4
- 实现 WebSocket 客户端
- 连接到发送端的信令服务器
- 处理基本的信令消息（连接状态、错误提示）
- 信令连接状态与 UI 同步

**阶段五验收**：接收端应用可在车机/平板上安装运行，能连接到发送端的信令服务器
---

## 阶段六：接收端 WebRTC（Week 7-8）

**目标**：接收端能通过 WebRTC 连接到发送端并播放视频流

### 功能点 6.1
- 集成 WebRTC 库到接收端
- 实现 WebRTCPeerManager 管理类
- 初始化 PeerConnectionFactory 和 PeerConnection
- 验证 WebRTC 初始化成功

### 功能点 6.2
- 创建 SurfaceViewRenderer 用于视频显示
- 设置为远端视频渲染目标
- 本地测试：渲染纯色/测试图案验证显示正常
- 确认 SurfaceView 生命周期管理正确

### 功能点 6.3
- 集成信令系统：与阶段五的 WebSocket 客户端对接
- 处理 SDP Offer/Answer 自动交换
- 实现 ICE 候选管理
- 连接状态监控和 UI 反馈

### 功能点 6.4
- 实现视频接收和渲染
- 远端视频流绑定到 SurfaceViewRenderer
- 视频显示优化（全屏、自适应分辨率）
- 统计信息日志输出（帧率、分辨率、延迟）

**阶段六验收**：接收端能通过 WebRTC 连接到发送端并显示视频流，延迟 < 500ms
---

## 阶段七：端到端集成（Week 9-10）

**目标**：发送端直连接收端，无需 PC 中转

### 功能点 7.1
- 统一双端信令协议
- 实现 mDNS 服务发现（发送端广播，接收端发现）
- 或实现 WebSocket 信令服务器（内嵌发送端）
- 验证双端能互相发现

### 功能点 7.2
- 自动 SDP 交换
- 发现后自动触发 Offer/Answer
- 无需用户手动复制粘贴
- 连接过程 UI 反馈（进度、错误提示）

### 功能点 7.3
- 端到端视频传输验证
- 发送端捕获 → 接收端渲染完整链路
- 延迟测量和优化
- 画质和流畅度调优

### 功能点 7.4
- 连接稳定性优化
- 断线重连机制
- 网络切换处理（WiFi 断开/恢复）
- 错误恢复和用户引导

**阶段七验收**：发送端和接收端在同一局域网内自动连接，稳定播放，延迟 < 300ms
---

## 阶段八：触摸回传（Week 11-12）

**目标**：实现车机触摸控制手机

### 功能点 8.1
- 接收端触摸采集
- 全屏触摸事件监听
- 坐标归一化（0-1 相对坐标）
- 通过 DataChannel 发送触摸事件

### 功能点 8.2
- 发送端接收触摸事件
- DataChannel 消息解析
- 坐标映射（车机分辨率 → 手机分辨率）
- 处理手机旋转场景

### 功能点 8.3
- 触摸注入实现
- Shizuku 方案集成（推荐）
- 或无障碍服务方案（备用）
- 注入成功验证（视觉反馈）

### 功能点 8.4
- 触摸体验优化
- 点击、滑动、长按手势支持
- 延迟优化（目标 < 100ms）
- 边缘 cases 处理（多点触控、快速滑动）

**阶段八验收**：在车机上点击/滑动，手机相应位置响应，体验流畅
---

## 阶段九：连接方式扩展（Week 13-14）

**目标**：支持多种连接方式

### 功能点 9.1
- WiFi Direct (P2P) 支持
- 实现 WiFi P2P 连接管理
- 无需路由器，双端直连
- 连接流程 UI 适配

### 功能点 9.2
- USB 网络共享支持
- 检测 USB 连接状态
- 固定 IP 段通信
- 最低延迟模式（可选）

### 功能点 9.3
- 蓝牙发现支持
- BLE 广播和扫描
- 仅用于交换 WiFi 凭证/IP
- 传输仍走 WiFi/USB

### 功能点 9.4
- 自动策略选择
- 根据当前网络环境推荐最佳连接方式
- 用户可手动覆盖
- 连接失败自动降级

**阶段九验收**：用户可在多种场景下成功连接（家里 WiFi、车内热点、USB 线）
---

## 阶段十：性能优化与发布（Week 15-16）

**目标**：生产级稳定性和性能

### 功能点 10.1
- 性能分级策略
- 自动检测车机性能
- 动态调整分辨率/帧率/码率
- 保活策略优化（车机后台限制）

### 功能点 10.2
- 车机适配
- Top 20 车机品牌测试
- OEM 定制系统兼容（比亚迪、吉利等）
- 分辨率适配（1920×720、1280×800 等）

### 功能点 10.3
- 驾驶安全合规
- 车速检测（如有 Car API）
- 驾驶模式简化 UI
- 免责声明和权限管理

### 功能点 10.4
- 发布准备
- 应用签名、图标、商店素材
- 隐私政策、用户协议
- 灰度发布和监控

**阶段十验收**：应用可在主流应用商店发布，用户可稳定使用
