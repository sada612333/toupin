## 性能优化与监控文档

### 一、现有性能基础
- 基于 WebRTC 传输的投屏过程中，存在画面延迟、声音不同步、采集/解码卡顿等问题
- 未实现性能监控功能
- 核心依赖：安卓原生音视频 API、WebRTC 传输 API

### 二、共性优化需求（适配双模块）

#### 1. 统一性能优化标准
- 投屏延迟 ≤ 300ms
- 帧率 ≥ 30fps
- 无明显音画不同步

#### 2. 优化数据传输链路
- 结合 WebRTC 带宽控制策略
- 压缩传输数据包

#### 3. 建立性能数据同步机制
- 确保双模块性能优化同步推进

### 三、模块专属性能优化

#### 发送端
- 优化屏幕采集清晰度，减少采集丢帧
- 优化音视频编码效率，降低编码耗时
- 集成性能采集逻辑，采集以下指标：
  - 编码耗时
  - WebRTC 传输耗时
  - CPU/内存占用
  - 投屏延迟
  - 画面帧率

#### 接收端
- 优化音视频解码速度，适配电视/盒子解码能力
- 优化画面渲染机制，减少显示丢帧，适配不同屏幕刷新率
- 集成性能采集逻辑，采集以下指标：
  - 解码耗时
  - 显示耗时
  - 音视频同步差
  - WebRTC 连接稳定性

### 四、性能监控统一规范

#### 1. 监控数据采集频率
- 关键指标实时采集（延迟、帧率）
- 资源占用定时采集（CPU、内存）

#### 2. 数据上报机制
- 异常数据即时上报
- 常规数据定时汇总上报

#### 3. 异常数据判定标准
- 延迟 > 300ms 判定为异常
- 帧率 < 30fps 判定为异常
- 音视频同步差 > 100ms 判定为异常

#### 4. 性能数据展示逻辑
- 在 Jetpack Compose 界面实时展示关键性能指标
- 提供性能趋势图表
- 异常状态醒目提示

### 五、编码要求
- 性能相关功能按单一功能点拆分（如采集性能优化、解码性能优化、数据采集）
- 每个功能点可独立验证、可测试，设计专属测试用例
- 日志输出遵循统一规范：
  - 重点标注性能模块、功能点、性能指标数据及异常信息
  - 便于定位性能相关问题

### 六、依赖适配
- 性能相关依赖组件（音视频 API、性能采集工具）需与 kitlon、gradle、安卓 gradle 插件适配
- 重构时若升级依赖，需提前排查版本冲突
