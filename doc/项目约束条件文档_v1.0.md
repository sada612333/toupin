## 项目约束条件文档

### 一、资源约束
- **开发人力**：[预留占位]
- **测试设备**：不同型号安卓手机、电视、盒子
- **算力支持**：适配 Jetpack Compose 开发及 WebRTC 调试需求
- **调试环境**：适配 kitlon、gradle、安卓 gradle 插件的调试环境

### 二、技术约束

#### 1. 平台适配
- 适配安卓 8.0 及以上版本
- 不使用废弃 API
- 遵循安卓 Material Design 设计规范及 Jetpack Compose 最佳实践

#### 2. 技术选型
- 编码/解码、连接（含 WebRTC）、性能采集优先使用安卓原生 API
- 减少第三方依赖
- 确保 Jetpack Compose 版本与 WebRTC 版本兼容

#### 3. 依赖管理
- 所有依赖组件以项目实际用到的为准
- 重构时可升级依赖组件，但需严格注意各组件与 kitlon、gradle、安卓 gradle 插件之间的适配性
- 提前排查并规避版本冲突

#### 4. 编码规范
- 编码时必须保证单一功能点可验证、可测试
- 每个功能点独立设计，支持单独测试
- 制定统一的日志结构规范，明确日志级别、输出格式、内容要求
- 确保日志可追溯、便于问题定位

### 三、时间约束
- 各优化模块、重构任务的截止时间：[预留占位]
- 确保整体项目进度

### 四、合规约束
- 不涉及隐私数据采集
- 仅获取投屏所需权限（屏幕采集、网络、存储、热点）
- 符合安卓应用权限规范
- WebRTC 传输过程中不泄露用户数据
