Android投屏发送端MVP产品与技术方案
一、方案概述
本方案针对Android投屏发送端MVP版本进行产品定义与技术落地设计，核心目标是实现轻量化、无后台部署、同局域网专属的屏幕投屏能力。产品仅聚焦基础投屏核心场景，摒弃冗余功能，严格遵循需求规则：本地设备承载服务、同局域网连接、屏幕+系统内音采集、差异化重连与异常提醒机制，快速完成可用、稳定的最小可行产品落地，满足基础投屏使用需求。
二、产品方案（MVP核心能力定义）
2.1 核心产品定位
轻量化Android投屏发送端工具，无需云端服务器，依托手机本地服务实现同局域网设备投屏，支持屏幕画面+系统内音同步传输，适配日常本地投屏基础场景，主打极简操作、低资源占用、规则化连接与异常容错。
2.2 核心功能详细定义
2.2.1 投屏开关控制（一键启停）
1.  提供可视化投屏启停按钮，支持一键开启投屏、一键结束投屏，操作极简，无复杂流程。
2.  结束投屏触发全局断连逻辑：点击结束投屏后，当前已连接的所有观看端设备立即停止画面、声音播放，同步断开链路，无残留连接。
3.  状态联动：投屏开启后按钮切换为“结束投屏”状态，投屏关闭后恢复初始状态，界面状态实时同步。
2.2.2 投屏数据源采集规则
1.  画面数据源：实时抓取Android设备完整屏幕画面，覆盖前台、后台应用、系统界面，支持全屏画面实时采集，无画面裁剪、无延迟偏移。
2.  音频数据源：仅采集手机系统内部声音，包含媒体播放、应用音效、系统提示音等设备内发声内容。
3.  采集排他规则：全程不收录麦克风外部环境声音，默认关闭麦克风采集通路，无额外开关，杜绝杂音混入投屏内容。
2.2.3 网络连接能力限制
MVP版本仅支持同局域网投屏连接，严格限制连接范围：仅WiFi同网段、同一局域网下的设备可发现、可连接，不支持外网、跨网段、4G/5G移动网络投屏，规避外网安全风险，简化链路复杂度。
2.2.4 断连重连规则
1.  网络异常判定：针对局域网波动、WiFi重连、设备短暂休眠等导致的链路中断，触发异常断连逻辑。
2.  重连权责划分：仅观看端执行自动重试重连，投屏发起端（本APP）不主动发起设备扫描、重连操作，保持发起端被动等待状态。
3.  状态保留：断连后发起端投屏服务持续运行，不主动停止投屏任务，等待观看端重连或用户手动结束投屏。
2.2.5 异常提醒机制
1.  主动异常弹窗提醒：仅针对APP发起投屏阶段的失败场景弹出提示弹窗，明确告知用户失败原因，包含权限被拒（屏幕采集权限、音频采集权限）、屏幕采集初始化失败、本地服务启动失败等核心异常场景。
2.  静默容错机制：观看端设备掉线、主动断开连接时，发送端不弹出任何提示、不震动、不主动终止投屏任务，静默等待新连接或用户操作，避免频繁弹窗干扰用户。
2.2.6 基础链路架构（无服务器）
全程无需部署云端后台服务器、本地局域网服务器，由Android手机APP自身承载投屏服务端能力，集成设备发现、链路传输、数据编码、连接管理等核心服务，实现点对点直连投屏，降低部署成本与运维难度，实现轻量化落地。
三、技术方案（MVP落地实现）
3.1 整体技术架构
采用移动端P2P点对点直连架构，无中心化服务，发送端APP集成Server服务能力，观看端作为Client主动接入，整体分为四层：设备发现层、链路传输层、数据采集编码层、异常逻辑层，全程本地运行、无外网请求、无后台依赖。
3.2 核心模块技术实现
3.2.1 投屏启停控制模块
1.  启动逻辑：用户点击开启投屏后，APP自动申请屏幕采集、系统音频采集权限，初始化本地投屏服务、编码通道、监听端口，完成后进入可连接状态。
2.  停止逻辑：用户点击结束投屏后，主动销毁所有音视频采集实例、关闭传输端口、清空所有连接会话，强制所有已接入观看端断连，重置投屏状态。
3.  状态锁机制：投屏运行期间锁定核心能力，避免重复启动、异常重启导致的功能冲突。
3.2.2 音视频采集模块（核心数据源）
1.  屏幕画面采集：基于Android MediaProjection API实现系统级屏幕采集，兼容Android 10及以上主流版本，支持动态分辨率适配，实时捕获屏幕帧数据，保障画面流畅度。
2.  系统音频采集：采用Android AudioRecord+系统音频路由机制，定向采集系统内部音频流，屏蔽麦克风音频通道，通过音频参数配置，彻底隔绝外部收音，确保投屏音频仅为设备内音。
3.  采集同步机制：音视频时间戳对齐，避免画面、声音不同步问题，保障投屏播放流畅性。
3.2.3 局域网设备发现与连接模块
1.  局域网限制：通过获取设备本地WiFi网段IP，校验接入设备IP，仅允许同网段设备接入，自动拦截跨网段、外网设备连接请求。
2.  本地服务监听：APP本地开启专属端口监听，作为服务端被动等待观看端设备扫描、连接，不主动扫描周边设备。
3.  多设备连接支持：支持同时接入多台观看端设备，实现一对多投屏传输，且启停操作可统一管控所有连接。
3.2.4 断连重连逻辑实现
1.  链路心跳检测：发送端内置心跳机制，定时检测与各观看端的连接状态，识别网络波动、设备掉线等异常断连场景。
2.  重连权限隔离：发送端仅监测连接状态，不执行任何重连逻辑，所有断连后的重试、重连操作全部由观看端自主完成。
3.  会话保留策略：临时断连后，发送端保留当前投屏编码、采集任务，不释放资源，等待观看端重连恢复投屏，无需用户重新开启。
3.2.5 异常捕获与提示模块
1.  启动阶段异常捕获：全覆盖权限拒绝（屏幕采集、音频采集权限）、服务初始化失败、采集通道开启失败、端口占用等启动异常。捕获后立即弹窗提示，展示标准化异常文案，支持用户重新尝试开启投屏。
2.  运行阶段异常静默处理：投屏运行中，观看端主动掉线、网络波动掉线、设备异常退出等场景，发送端无弹窗、无提示，维持当前投屏运行状态，不干扰用户操作。
3.2.6 无服务端链路实现
1.  摒弃云端后台、本地服务器部署，所有核心能力（设备监听、数据编码、P2P传输、连接管理）全部集成于Android客户端内。
2.  基于UDP/TCP混合协议实现局域网P2P通信：设备发现采用UDP广播，音视频数据传输采用TCP可靠传输，兼顾发现效率与传输稳定性。
3.  轻量化资源占用：全程本地运算，无外网数据交互，低功耗、低内存占用，适配主流Android手机机型。
3.3 核心技术参数（MVP标准）
1.  支持系统：Android 10及以上版本（覆盖主流机型）
2.  网络环境：仅限同一WiFi局域网，不支持移动网络、外网
3.  采集内容：全屏屏幕画面+系统内音，无麦克风收音
4.  连接模式：发送端被动服务、观看端主动连接
5.  部署模式：纯客户端实现，无任何服务端部署依赖
四、MVP版本范围界定（做与不做）
4.1 MVP必做能力
1.  一键启停投屏，全局断连管控能力；
2.  屏幕画面+系统内音精准采集，屏蔽麦克风声音；
3.  同局域网P2P直连，无后台服务器部署；
4.  观看端自动重连、发送端不主动重连的规则落地；
5.  启动异常弹窗提示、运行掉线静默处理的差异化提醒。
4.2 MVP暂不做能力
1.  不支持外网、跨网段、蓝牙投屏；
2.  不支持麦克风声音采集、音视频自定义参数调节；
3.  不支持投屏录制、截图、画质帧率自定义设置；
4.  不支持发送端主动重连、设备自动发现配对；
5.  无后台数据统计、日志上报、设备管理功能。
五、异常场景全覆盖说明
1.  权限异常：用户拒绝屏幕采集/音频权限，启动投屏弹窗提示“权限不足，请开启对应权限”，投屏启动失败；
2.  采集异常：系统通道占用、采集初始化失败，弹窗提示“投屏启动失败，请重试”；
3.  网络异常：局域网WiFi波动、断连，观看端自动重试，发送端静默无提示；
4.  设备掉线：观看端主动退出、关机掉线，发送端静默维持投屏状态，不弹窗、不停止任务；
5.  端口异常：本地端口被占用，自动切换备用端口，启动失败则弹窗提示异常。
