## 测试模块文档

### 一、测试目标
- 验证基础投屏功能及 WebRTC 局域网传输稳定性
- 验证各优化点效果（含连接、性能、界面）
- 确保优化后无新增问题，兼容 Jetpack Compose 框架及 WebRTC 版本
- 验证单一功能点的可测试性、可验证性
- 检查日志输出是否符合规范
- 验证依赖组件升级（若有）后与 kitlon、gradle、安卓 gradle 插件的适配性，无版本冲突
- 验证核心模块与补充文档（连接细节、性能优化与监控）的衔接流畅性

### 二、测试类型

#### 1. 单元测试
- 针对核心逻辑、工具类、连接/性能采集逻辑、Jetpack Compose 组件、WebRTC 传输核心逻辑
- 重点测试单一功能点的正确性，确保每个功能点可独立验证

#### 2. 集成测试
- 针对模块间交互：
  - 发送端与接收端连接
  - WebRTC 数据传输
  - 性能数据同步
  - Jetpack Compose 界面与业务逻辑交互
  - 核心模块与补充文档衔接

#### 3. 性能测试
- 针对核心性能指标（参考性能优化与监控文档）：
  - 投屏延迟
  - 帧率
  - WebRTC 连接稳定性
  - 音视频同步差

#### 4. 兼容性测试
- 针对不同安卓机型、安卓版本
- 覆盖发送端、接收端及各连接方式
- 验证 Jetpack Compose 界面适配性及 WebRTC 版本兼容性
- 验证依赖组件与 kitlon、gradle、安卓 gradle 插件的适配性

### 三、核心测试用例
- 基础投屏流程
- WebRTC 局域网传输稳定性
- 界面适配（多机型）
- 多连接方式切换（参考连接细节文档）
- 性能异常场景（参考性能优化与监控文档）
- 重构后功能验证
- Jetpack Compose 组件复用性测试
- 单一功能点验证测试
- 日志规范符合性测试
- 依赖组件适配性测试
- 核心模块与补充文档衔接测试

### 四、测试标准
- 投屏延迟 ≤ 300ms
- 帧率 ≥ 30fps
- WebRTC 连接成功率 ≥ 98%
- 无明显音画不同步
- 适配主流安卓机型
- 连接切换流畅无异常
- Jetpack Compose 界面显示正常、操作流畅
- 单一功能点可独立验证、测试通过
- 日志输出符合统一规范，级别清晰、格式统一、内容可追溯
- 依赖组件与 kitlon、gradle、安卓 gradle 插件适配，无版本冲突
- 核心模块与补充文档衔接顺畅，无逻辑矛盾

### 五、测试结果反馈机制
- 记录测试异常，关联对应优化模块及补充文档
- 同步至开发端
- 重点标注 Jetpack Compose 界面、WebRTC 传输、单一功能点测试、日志规范及依赖适配相关异常
